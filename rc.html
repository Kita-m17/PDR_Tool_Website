Abstract

Abstract

Defeasible reasoning is a form of non-monotonic reasoning that allows conclusions to be revised when new or more specific information is introduced, closely mirroring how humans reason in everyday life. Despite its growing importance in AI and knowledge representation, defeasible reasoning has not yet been widely incorporated into logic education, and existing defeasible reasoning tools provide results and explanations but offer limited support for step-by-step inspection of the intermediate computational states of the reasoning process. This paper presents a web-based explanation tool for defeasible reasoning, developed as part of a broader collaborative system that also includes Lexicographic and Relevant Closure, implemented by other group members. The tool provides a debugger-style step-through interface that exposes the BaseRank construction and Rational Closure entailment process, presenting computational states alongside plain-English explanations and formal pseudocode. A dedicated drowning problem example explains a known limitation of Rational Closure, while a comparison mode allows users to observe how Rational Closure, Lexicographic Closure, and Relevant Closure process the same knowledge base and query. A guided tutorial further supports exploration of the system. The tool is evaluated through manual verification, automated unit testing, comparison with existing implementations, comparative analysis of the supported entailment methods, execution-time observations, and informal expert feedback. The results provide evidence that the implementation behaves consistently with the theoretical algorithms and that the interface makes the intermediate reasoning process easier to inspect and interpret.

Introduction

Computing an answer is not the same as understanding it

Classical logic cannot take a conclusion back when new information arrives, so it handles exceptions badly. Defeasible reasoning fixes this, and Rational Closure is one of its key entailment algorithms. For someone who knows classical logic and is meeting defeasible reasoning for the first time, the algorithm is hard to follow: seeing the final answer is not the same as understanding the steps that produced it.

Research question

How can Rational Closure be presented in a way that makes its intermediate reasoning process easier to inspect and interpret, while also supporting comparison with other defeasible entailment methods?

Methodology & contribution

Making Rational Closure inspectable

Rational Closure was largely redeveloped from EXTRC to follow Casini and Meyer's definition closely, and now records its state at every iteration: the working set, the exceptionality check, and any rank removed. The step-through replays these states one at a time, each with the matching line of pseudocode and a plain-English explanation. It builds on the components developed as a group, such as BaseRank and the shared step-through layout.

Rank removal

While the query's antecedent is exceptional, the lowest rank is highlighted, greyed out and struck through, so learners can watch each rank being removed as it happens.

Justifications

"Show Details" gives a classical justification (adapted from Wang): the smallest set of formulas behind an exceptionality result. A weak justification explains the final entailment check.

The drowning problem

A dedicated example shows Rational Closure's best-known limitation in context, marking the statement that caused the contradiction and the unrelated statement that was drowned with it.

Comparison

Comparing all three algorithms

Comparison mode runs Rational, Lexicographic and Relevant Closure on the same knowledge base and query, in five steps: the shared BaseRank, where the methods diverge, each full step-through, whether each formula is kept, weakened or removed, and finally each method's answer.

Evaluation & results

Does it work?

The tool was evaluated on correctness, execution time and informal expert feedback. A formal user study was outside the scope of the project.

All matched

Manual verification

Expected outputs were worked out by hand for entailments, non-entailments, multi-rank knowledge bases and edge cases, and the intermediate steps were checked to follow the order the algorithm prescribes.

Passing

Unit tests

Cover entailment and non-entailment, rank removal in the drowning problem, and the justifications used in the explanations.

Consistent

Existing tools

The same knowledge bases and queries were run through EXTRC and Hamayobe's implementation, and the answers matched on every test case.

0.13 s → 1.00 s

Execution time

The average time per query rose from 0.13 s for 3 statements to 1.00 s for 30 statements (mean of five runs). Capturing every step trades some speed for transparency.

Expert feedback

Clear, step-by-step explanations

Members of UCT's AI research group found the explanations clear, with no issues in the reasoning, and highlighted the step-by-step approach as a strength.

One reviewer noticed "Show Details" didn't always show the formulas that caused an exceptionality result, so it was rebuilt to use classical justifications.

Discussion & conclusion

What it shows

Key findings

  • The interface exposes states that match the BaseRank and Rational Closure algorithms.
  • Learners can see how the drowning problem happens, not just that it does.
  • Methods can reach the same answer in different ways, which only the steps reveal.

Limitations

  • No formal user study, so effects on learning are not measured.
  • Capturing every step costs speed on larger knowledge bases.
  • The drowning problem is shown with a predefined example, not detected automatically.
  • Input uses logical notation, not natural language.

Future work

  • A formal user study of learning outcomes.
  • Caching and larger scaling experiments.
  • Automatic detection of the drowning problem.
  • Natural-language versions of statements, such as "birds typically fly".

Conclusion

This work presents a step-through tool that makes Rational Closure inspectable: it shows BaseRank and Rational Closure one step at a time, explains each step in pseudocode and plain English, demonstrates the drowning problem in context, and compares Rational Closure with Lexicographic and Relevant Closure on the same query. It lays a foundation for future user studies and for extending step-through explanations to other defeasible reasoning algorithms.
