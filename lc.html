Abstract

Abstract

Defeasible reasoning is a form of non-monotonic reasoning that allows conclusions to be revised when new or more specific information is introduced. Lexicographic Closure is an entailment algorithm that handles these exceptions while preserving as much relevant information as possible. Existing tools often focus on the final entailment result rather than clearly showing how that result was reached. This paper presents the Lexicographic Closure component of PDR-Tool, a web-based pedagogical debugger-like tool for explaining defeasible reasoning. The tool provides a step-through interface that presents the reasoning process alongside the formal algorithm and plain-English explanations. In particular, it exposes the intermediate checks performed when Lexicographic Closure resolves conflicting information. The implementation was evaluated for correctness against existing implementations and for faithfulness by comparing the displayed steps with the reasoning performed by the backend. The results show that the tool produces the expected entailment results while providing a detailed and faithful representation of the Lexicographic Closure process.

Introduction

The answer doesn't show how the rank was weakened

When a rank conflicts with a query, Rational Closure discards the whole rank, even if only one statement causes the conflict: the drowning problem. Lexicographic Closure avoids this by testing smaller and smaller subsets of the rank and keeping as much information as possible. But its final answer says nothing about how the rank was weakened, or which information was rejected along the way.

Aim

How much of Lexicographic Closure's subset-based rank weakening can be exposed through a step-through interface, while staying faithful to the algorithm and keeping the entailment result correct?

Methodology & contribution

Making rank weakening visible

Earlier implementations test all subsets of a given size in one combined check, which gives the right answer but hides which subset worked. This reasoner checks each subset separately, recording every check (including the ones that fail) while the algorithm runs, so the step-through only ever shows what the reasoner actually did. The pseudocode follows Hamayobe's Algorithm 3.5. It builds on the components developed as a group, such as BaseRank and the shared step-through layout.

Rank weakening

A weakened rank shows its original statements struck through, with the replacement formula underneath. Each step covers one subset size, so the shrinking rank stays easy to follow.

Every subset checked

Each sub-knowledge base is listed with whether it still refutes the query's antecedent. Failed subsets are kept, so it's clear why the algorithm had to move to a smaller size.

Justification

The final step shows the surviving knowledge base, the final entailment check, and a justification: the smallest set of surviving statements that entails the query on its own.

Comparison

Compared with Rational Closure

The Garfield example shows the difference. Cats are typically active, have fur and like Mondays, but Garfield is a cat who is not active and doesn't like Mondays. Does Garfield typically have fur?

Evaluation & results

Does it work?

The tool was evaluated on correctness, on whether the steps shown faithfully match the reasoner, on informal feedback, and on the cost of exposing every subset check.

All matched

Existing implementations

Five test knowledge bases, covering cases from multiple subset sizes to an antecedent inconsistent with rank ∞, gave the same results as Moloi's and Hamayobe's implementations.

Matched

Worked by hand

Expected results were worked out from the algorithm's definition for entailments, non-entailments, no weakening, a weakened rank, and a rank removed completely.

Passing

Unit tests

Cover entailed and non-entailed queries, exceptional antecedents, unsupported conclusions, the drowning problem, and specific exceptions overriding general defaults.

Faithful

Faithful to the reasoner

The subsets, working knowledge base, ranking changes and highlighted pseudocode shown at each step all matched the state recorded by the reasoner.

Up to 2n checks

The cost of the detail

Checking subsets one by one can take up to 2n satisfiability checks for a rank of n statements, compared with at most n for a combined check, so the tool suits small knowledge bases.

Expert feedback

Clear and useful

Members of UCT's Logic-Based AI research group found the algorithm clear, and singled out the display of the sub-knowledge bases as a useful part of the interface.

Discussion & conclusion

What it shows

Key findings

  • Grouping subsets by size gives enough detail to follow the weakening, without an overly long trace.
  • The failed subsets are part of the explanation: they show why a subset size was rejected.
  • The extra trace information doesn't change the final result in any tested case.

Limitations

  • No formal user testing, so effects on learning are not measured.
  • The number of subsets grows exponentially with the size of the rank, so larger knowledge bases are slower and produce longer traces.

Future work

  • Support more defeasible entailment algorithms for comparison.
  • Reduce the number of subsets checked, while keeping the trace.
  • An AI assistant grounded in the algorithms and traces.
  • Natural-language input and automatic drowning-problem detection.

Conclusion

This work presents a step-through interface for Lexicographic Closure's rank weakening. Every subset the reasoner checks is recorded, including those that fail, and shown grouped by subset size: which subsets were considered, why a size was rejected, and how the final result was reached. The results agreed with existing implementations, and the displayed steps matched the reasoner's recorded state. The result is a faithful and more granular view of Lexicographic Closure that can support future evaluation and pedagogical tools.
